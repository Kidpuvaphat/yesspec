# ชุดข้อมูลอันดับล่าสุด

หน้าแรก หน้าอันดับ และหน้าเปรียบเทียบใช้ `assets/ranking-data.js` ร่วมกัน ตั้งแต่ตรวจรหัสรายการ/หลักฐานยอดขาย ผูกสเปกและราคากรอกเอง จนถึงรับมือคำขอที่ตอบสลับลำดับและโหลดไม่สำเร็จ แต่ละหน้ายังจัดการตัวกรองและการแสดงผลของตนเอง

## ขอบเขต

- `create({fetcher, host})` สร้าง module สำหรับหนึ่งหน้าจอ; `load(refresh)` อ่าน snapshot และ `watch(listener)` ติดตามการเปลี่ยนข้อมูลพร้อมคืนคำสั่งหยุดติดตาม
- snapshot ประกอบด้วย `dataset`, `audit`, `status`, `message`; สถานะคือ `ready`, `prices_unavailable` หรือ `unavailable`
- ทุกการอ่านใหม่ข้าม HTTP cache สำหรับ feed สเปก ราคากรอกเอง และรายการตรวจหลักฐาน; การเรียกซ้ำก่อนรีเฟรชใช้ snapshot พร้อมใช้เดิม
- จำกัดเวลาการอ่านแต่ละไฟล์ 15 วินาที รวมการอ่านเนื้อหา JSON และยกเลิกคำขอเมื่อเบราว์เซอร์รองรับ เพื่อไม่ให้คำขอค้างขวางการรีเฟรชครั้งต่อไป
- คำขอเก่าทั้งที่สำเร็จและล้มเหลวคืนผลของคำขอล่าสุด จึงไม่สามารถล้างหรือคืนราคาเก่าทับข้อมูลใหม่
- เมื่ออ่านทะเบียนราคาไม่ได้หรือรูปแบบผิด ใช้ feed ที่ตรวจแล้วกับทะเบียนราคาว่างแบบไม่พร้อมใช้ ไม่คืนลิงก์หรือราคาเดิมที่อาจถูกล้างไปแล้ว
- เมื่อ feed ผิดหรือโหลดไม่ได้ ไม่ผูกราคาใหม่เข้ากับ feed เก่า ใช้รายการที่เคยตรวจแล้วโดยพักอันดับตามสูตรเดิม ครั้งแรกที่ยังไม่มีรายการจะแสดงปุ่มลองใหม่
- โหลดสเปกเพิ่มเติมหรือรายการตรวจหลักฐานไม่ได้ ไม่ทำให้ feed และราคาที่ตรวจผ่านใช้ไม่ได้
- กลับแท็บ, focus, เหตุการณ์ `yesspec_offers_updated` และทุก 60 วินาทีขณะหน้าแสดงอยู่ ทำให้รีเฟรช; เหตุการณ์ระหว่างโหลดรวมเป็นการอ่านตามหลังอีกครั้ง เมื่อหยุดติดตามจะถอดเหตุการณ์และ timer

`assets/phone-value.js` และ `assets/ranking-offers.js` คงเดิมทั้งไฟล์ รวมสูตร น้ำหนัก ความตรงกันของตัวเลือก อายุราคา ป้ายประมาณการ และเกณฑ์พักอันดับเมื่ออ่านข้อมูลที่ผู้ดูแลยืนยันไม่ได้ การรวม module ไม่สร้างราคาใหม่หรือเปลี่ยนลิงก์ Affiliate

## การทดสอบ

ทดสอบผ่าน interface ของ module ด้วยข้อมูลที่จับคู่จริงและตัวคำนวณเดิมทั้ง 6 โหมด รวมคำขอช้า ผลเก่าตอบทีหลัง ทะเบียนราคาเสีย feed เสีย การกลับมาใช้งาน และการหยุดติดตาม ส่วน tests หน้าจอยืนยันการเชื่อม module กับตัวกรองและรุ่นที่เลือก การตรวจในเบราว์เซอร์ใช้ข้อมูลสำเนาชั่วคราว ไม่บันทึกราคาทดสอบลงเว็บจริง
