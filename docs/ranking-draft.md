# ฉบับร่างราคาและตะกร้า

`assets/ranking-draft.js` เป็น module ที่เก็บกฎการแก้ฉบับร่างหนึ่งรายการ หน้าจอหลังบ้านส่งเจตนาการแก้ไขและอ่านค่ากลับไปแสดงผล โดยไม่แก้ state ภายในโดยตรง

- `create(row)` เก็บข้อมูลตั้งต้นและ revision ของรายการนั้น ไม่แก้ข้อมูลจากเซิร์ฟเวอร์
- `view()` คืนสำเนาสำหรับวาดฟอร์ม; การแก้สำเนาไม่เปลี่ยนฉบับร่าง
- `change(intent)` รองรับแก้ราคาอ้างอิง สเปก เลือก RAM/ความจุ และแก้/ล้าง/คืนต้นทาง/ยืนยันซ้ำของตะกร้า
- `changes()` คืนเฉพาะข้อมูลที่เปลี่ยน หรือ `null`; `prepare()` ตรวจลิงก์และราคาก่อนคืนข้อมูลที่จะส่งบันทึก เซิร์ฟเวอร์ยังตรวจข้อมูลและ revision ซ้ำตามเดิม
- `beginCheck(platform)` สร้างบริบทการตรวจสำหรับฉบับร่างปัจจุบัน; `confirmCheck(context, result, index, confirmation)` รับเฉพาะตัวเลข THB ที่เลือกและยืนยันชนิดราคา/ตัวเลือก/เงื่อนไขแล้ว โดยไม่เปลี่ยน URL Affiliate

ราคาอ้างอิงแยกจากราคาตะกร้าเสมอ การเปลี่ยนลิงก์ล้างเฉพาะราคา ชนิดราคา ตัวเลือก เงื่อนไข และหลักฐานของตะกร้าเก่า การแก้สเปกหรือเลือกความจุต้องยืนยันสเปกใหม่ ราคาและสเปกที่ไม่แก้ไม่ถูกส่งกลับไปบันทึก จึงไม่เปลี่ยนเวลาเดิมหรือเปลี่ยนสเปกวิจัยเป็นสเปกกรอกเองโดยอ้อม

ผลตรวจผูกกับฉบับร่างและลำดับการแก้ไข การแก้แล้วคืนค่าเดิม การเปลี่ยนสเปก การเริ่มตรวจรอบใหม่ หรือการโหลดฉบับใหม่ ทำให้ใช้ผลตรวจเก่าไม่ได้ การยืนยันสำเร็จยังเป็นฉบับร่างและรับผลตรวจชุดเดิมซ้ำไม่ได้ `assets/price-check.js` รับผิดชอบเฉพาะหน้าต่างตรวจ การยกเลิกคำขอ และส่งตัวเลือกที่ผู้ใช้ยืนยันเข้ามา

หน้าจอเป็น adapter ของการโหลด/บันทึกผ่าน HTTP: บันทึกไม่สำเร็จต้องเก็บฉบับร่างและ revision เดิม หากบันทึกสำเร็จแต่โหลดกลับไม่สำเร็จ แสดงสถานะว่าบันทึกแล้วและรออ่านข้อมูลล่าสุดก่อนเปิดแก้ต่อ เพื่อไม่ส่ง revision เก่าซ้ำ การบันทึกรายการเดียวเก็บฉบับร่างรายการอื่นไว้ และการกดโหลดล่าสุดเพื่อล้างฉบับร่างจะล้างหลังอ่านข้อมูลสำเร็จเท่านั้น

ไม่เปลี่ยนรูปแบบทะเบียนข้อมูล การตรวจ revision/การบันทึกทั้งชุดใน `ranking_offers.py` หรือสูตรคะแนนใน `phone-value.js` และ `ranking-offers.js` ไม่ย้ายหรือเขียนทับราคากับลิงก์ที่อยู่บนเซิร์ฟเวอร์

ทดสอบผ่าน interface ของฉบับร่าง หน้าต่างตรวจราคา และการเรียกผ่านหน้าจอหลังบ้าน รวมผลตรวจล่าช้า การบันทึก/อ่านกลับล้มเหลว และการเก็บข้อมูลที่ไม่แก้ ใช้ชุดทดสอบฝั่งเซิร์ฟเวอร์เดิมยืนยัน revision และการบันทึกทั้งชุด
